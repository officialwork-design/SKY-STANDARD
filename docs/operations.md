# 運用・障害対応

## 日常運用

| 作業 | 場所 | 内容 |
|---|---|---|
| 問い合わせ対応 | 「問い合わせ管理」 | `対応状況`（未対応→対応中→完了）、`担当者`、`回答日時` を更新。返信は LINE Official Account Manager のチャットから |
| FAQ 更新 | 「FAQ」 | `質問・キーワード` はカンマ・「・」・「/」区切りで複数指定可。`有効`=ON/OFF、`要有人確認`=YES で問い合わせ導線を追加 |
| 通知文面 | 「通知テンプレート」 | `{{予約ID}}` `{{搭乗日時}}` `{{プラン名}}` `{{人数}}` `{{集合場所}}` が使用可。`有効`=ON のみ送信 |
| 運航変更・欠航案内 | 「送信ログ」 | `結果`=承認待ち の行を選択 → メニュー「予約・通知 → 承認待ち通知を送信（選択中の行）」/「選択中の通知を却下」 |
| ID・URL 変更 | 「ID管理」 | B列を編集（コード変更不要）。リッチメニューの URL は「LINE管理 → リッチメニュー登録・更新」を再実行 |
| 配信数確認 | メニュー「LINE管理 → 今月の配信数確認」 | プッシュ通知は月間メッセージ数を消費（応答メッセージは消費しない） |

### 多言語対応（拡張）

- 「顧客管理」の `言語` は LINE プロフィールの言語で自動入力されます。
- 通知テンプレートに `BOOKING_CONFIRMED_en` のような `ID_言語` 行を追加すると、その言語の利用者にはそちらが優先されます（なければ日本語）。

### マーケティング配信（拡張）

- 「顧客管理」の `同意状況` を配信対象の判定に使用してください。一斉配信は LINE Official Account Manager の配信機能、またはナローキャスト API を利用し、本システムのプッシュ通知（取引通知）とは分けて運用することを推奨します。

## 送信ログの「結果」

| 値 | 意味 | 対応 |
|---|---|---|
| 成功 | 送信完了 | — |
| 承認待ち | 運航案内。担当者の承認待ち | 承認または却下 |
| 失敗(再試行待ち) | 一時エラー（429/5xx/通信） | 自動再送（最大 3 回） |
| 失敗 | 恒久エラー（400 等）または再送上限 | エラー内容を確認。管理者へ通知済み |
| 対象なし | 予約に LINE ユーザーが紐付いていない | 必要なら電話・メールで連絡 |
| 対象外(ブロック) | 利用者がブロック中 | — |
| テンプレート無効 | テンプレートが OFF/未登録 | 文面を確認して ON |
| 承認却下 | 担当者が却下 | — |
| 古いイベント(スキップ) | 予約サイトから順序が逆転したイベント（`occurredAt` が反映済みより古い） | 予約サイト側の状態を確認 |
| 処理中 | 送信中。15 分以上残った場合は再送トリガーが自動で再送 | — |

## 障害時の確認手順

0. **「エラーログ」シート**（メニュー「システム管理 → エラーログを開く」）— 未対応の FATAL / ERROR を確認し、対応後は「対応状況」を更新する。詳細は [errorlog.md](errorlog.md)。

1. **メニュー「システム管理 → 接続・設定診断」「初期設定 → ID・URL設定チェック」** — 未設定・形式エラー・秘密情報のシート入力がないか。
2. **GAS 実行ログ** — エディタ左の「実行数」。`level: ERROR` の `event` を確認。
   - `config.missing`: スクリプトプロパティ不足
   - `webhook.invalid_event` / `webhook.invalid_destination` / `webhook.destination_mismatch`: 形式不正・宛先違いの受信（偽造の可能性。処理はしていません）
   - `webhook.unfollow_unconfirmed`: 未確認のブロック通知を無視
   - （relay のみ）`webhook.bad_signature` / `webhook.stale`: リレーと GAS の鍵不一致・時刻ずれ
   - `webhook.event_failed`: 応答失敗（`Invalid reply token` は応答期限切れ）
   - `notify.push_failed`: 通知失敗（送信ログに詳細）
3. （relay のみ）**リレーのログ**（Cloud Run → ログ）
   - `relay.bad_signature`: LINE の Webhook URL / チャネルシークレットの不一致
   - `relay.forward_failed`: GAS_WEBAPP_URL の誤り・GAS 障害
4. **LINE Developers** — Webhook の「検証」、「統計情報」のエラー率。
5. **アクセストークン失効** — 401 が出る場合はトークンを再発行してスクリプトプロパティを更新。
6. **予約確認が表示されない**
   - 「予約管理」に `LINEユーザーID` が入っているか（予約サイトから連携されているか）
   - LIFF のチャネルと Messaging API のチャネルが同一プロバイダーか
   - ID管理の `LINE_LOGIN_CHANNEL_ID` が LIFF のチャネルIDと一致しているか
7. **二重送信の疑い** — 「送信ログ」で同じ `冪等キー` の行が1行のみであることを確認。

## セキュリティ運用

- アクセストークン・シークレットは定期的にローテーション（GAS プロパティとリレーの Secret を同時更新）。
- スプレッドシートの共有範囲は運営メンバーに限定（顧客の LINE ユーザーID・問い合わせ内容を含むため）。
- GAS単体構成では Webhook の送信元を検証できません。Web アプリの URL を不用意に公開しない（ただし秘密にしても署名検証の代わりにはならない）。不審な受信が増えたら「接続・設定診断」と実行ログを確認する。
