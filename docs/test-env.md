`src/test-env/TestEnv.gs` は、次のいずれかに当たると何もせずに止まります：本番の GAS プロジェクトで実行した／`SPREADSHEET_ID` が本番のシート／LINE トークンが @686mdyho のもの。

## 1. テスト用 GAS 一式を作る

```bash
node tools/test-env/build.js
```

`build/test-env/` に、本体のコード（src/gas）＋ `zz_TestEnv.gs` ＋ テスト用 `appsscript.json`（JPEG をドライブに保存するため `drive` スコープ。本番は `drive.readonly` のまま）が出力されます。`all-in-one.gs` は全ファイルを1つにまとめたものです。

## 2. テスト用 LINE チャネルを作る（お客様の作業）

1. LINE Developers → 本番と同じプロバイダー → 「新規チャネル作成」→ Messaging API（名前の例：SKY STANDARD テスト）
2. 「Messaging API設定」→ チャネルアクセストークン（長期）を発行
3. LINE Official Account Manager（テスト用アカウント）→ 応答設定：**チャット ON／Webhook ON／応答メッセージ OFF／あいさつメッセージ OFF**
4. テスト用アカウントの QR コードをスマホで読み取って友だち追加は、**手順 4 の後**に行う

トークンはチャットやシートに貼らず、手順 3 のスクリプトプロパティにだけ入力してください。

## 3. テスト用 GAS プロジェクトを作る

**Apps Script エディタの場合**
1. script.google.com → 新しいプロジェクト（名前の例：SKY STANDARD LINE テスト）
2. プロジェクトの設定 →「appsscript.json マニフェスト ファイルをエディタで表示する」を ON → `build/test-env/appsscript.json` の内容に置き換え
3. `コード.gs` の中身を `build/test-env/all-in-one.gs` の内容に置き換えて保存
4. プロジェクトの設定 → スクリプト プロパティに `LINE_CHANNEL_ACCESS_TOKEN`（テスト用チャネルのトークン）を追加

**clasp の場合**：`build/test-env/.clasp.json.example` をテスト用スクリプトIDで `.clasp.json` にして、`build/test-env` で `clasp push`。

## 4. 初期設定（エディタの「実行」）

| 順 | 関数 | 内容 |
|---|---|---|
| 1 | `testSetup` | テスト用スプレッドシートを作成。WEBHOOK_MODE=direct、ADMIN_USERS・ADMIN_EMAIL=実行者（運営通知はこのメールに届く）。初回は Google の承認画面が出ます |
| 2 | `testMakeRichMenuImage` | 1MB 以下の JPEG を同じフォルダに別名で作成し、元画像が変わっていないことを確認。テスト用 ID管理 の RICHMENU_IMAGE_FILE_ID に設定 |
| 3 | デプロイ | 「デプロイ」→「新しいデプロイ」→ ウェブアプリ（次のユーザーとして実行：自分／アクセス：全員）→ URL をコピー |
| 4 | `testSetup`（再実行） | ウェブアプリの URL を GAS_WEBAPP_URL に記録 |
| 5 | LINE Developers | テスト用チャネルの Webhook URL にウェブアプリの URL を設定 →「Webhookの利用」ON |
| 6 | `testCheck` | トークン・チャット設定・Webhook 疎通・4領域の定義・画像を確認（LINE には登録しない） |
| 7 | `testDeployRichMenu` | **テスト用チャネル**にリッチメニューを登録 |
| 8 | スマホ | テスト用アカウントを友だち追加 |
| 9 | `testSeedReservations` | 友だち追加した本人の予約2件（確定・キャンセル済み）と他人の予約1件を登録。予約IDがログに出ます |

## 5. スマホでの確認項目

結果は `testStatus` とテスト用スプレッドシートで確認します。モック環境での同じ確認の結果は [test-reports/2026-10-30-mock.md](test-reports/2026-10-30-mock.md)（`node tools/test-env/scenario.js`）。

**A. リッチメニュー（4領域）**
- [ ] 画像が4領域（上部全面・下段3つ）で表示され、文字の位置とタップ位置が合っている
- [ ] 「ご予約はこちら」→ 準備中の案内
- [ ] 「よくある質問」→ 準備中の案内
- [ ] 「予約確認」→ 予約IDの入力案内
- [ ] 「お問い合わせ」→ 4項目のボタン

**B. 予約確認（LINE 連携済みのデータのみ）**
- [ ] `12345` → 形式違いの案内（3回で終了）
- [ ] 本人の確定予約（`TEST-…-A1B2C3`）→ 予約内容＋［予約変更］［キャンセル］［オペレーターに相談］。氏名・金額は出ない
- [ ] ［予約変更］→ 担当者が承る案内／［キャンセル］→ 規定の案内と「キャンセルされておりません」。シートの予約状態は変わらない
- [ ] 本人のキャンセル済み予約（`…-D4E5F6`）→［予約変更］で「お受けできません」
- [ ] 他人の予約（`…-0C0C0C`）・存在しない ID → 同じ文面で「確認できませんでした」＋オペレーター導線
- [ ] ［入力をやめる］で終了／10分放置で終了

**C. お問い合わせ4項目**
- [ ] フライト予約について → 準備中の案内＋オペレーター導線（受付IDは出ない）
- [ ] チャーター見積 → 6項目の案内 → 送信 → 受付ID（INQ-…）。料金は出ない
- [ ] その他のお問い合わせ → 送信 → 受付ID
- [ ] オペレーターに相談 → 送信 → 受付ID（予約カードから押した場合は予約IDが添えられる）
- [ ] 問い合わせ管理に1件ずつ保存（対応状況=未対応、自動返信有効=FALSE）。運営通知メールが届く

**D. オペレーター切替・自動返信停止**
- [ ] 受付後に「こんにちは」「FAQ」・リッチメニューのタップ → **何も返信しない**
- [ ] LINE Official Account Manager のチャットに受信が表示され、担当者として返信できる
- [ ] シートで自動返信有効を TRUE（または `testResumeAutoReply`）→ 次のメッセージから自動返信が再開

**E. その他**
- [ ] グループに招待して「予約確認」→ 1対1トークへの案内（予約内容は出さない）
- [ ] `testStatus` のエラーログが 0 件（または内容を確認）

## 6. 後片付け・本番反映（承認後）

- テスト用チャネル・GAS・スプレッドシートは削除しなくても本番に影響しません。
- 本番反映（承認後）：本体 GAS へ反映 → ウェブアプリを新バージョンで更新 → 本番 ID管理 の `RICHMENU_IMAGE_FILE_ID` を作成した JPEG のファイルIDに変更 → 管理メニュー「リッチメニュー設定確認」→「リッチメニュー登録・更新」。手順は README「0. 公式LINEの構成とフロー」。
