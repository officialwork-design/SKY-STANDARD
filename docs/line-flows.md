## 2. ご予約はこちら

LINE 側に予約フォームは作りません。公式サイトで「地域 → プラン → コース → 搭乗日時・人数・搭乗者情報 → 予約申請 → 運航確認 → 決済案内 → 決済確認後に予約確定」と進みます（予約サイトの既存フロー）。

公式サイトは未公開のため、`BOOKING_SITE_URL` は未設定です。仮 URL は設定しません。公開後に ID管理へ入力し、「リッチメニュー登録・更新」を実行するとリンクに切り替わります。

## 3. 予約確認（LINE トーク）

```text
「予約確認」→ 予約IDを入力してくださいませ（例：SKY-20261101-A1B2C3）
  └ 予約IDを送信
      ├ 形式が違う → 再入力（3回で終了・オペレーター導線）
      ├ この LINE アカウントに紐づく予約 → 予約内容を表示 ＋ [予約変更][キャンセル][オペレーターに相談]
      └ 紐づいていない（または存在しない）
          ├ 予約サイト API あり → 電話番号またはメールアドレスで本人確認 → 一致で紐づけて表示／不一致は表示しない
          └ 予約サイト API なし → 「確認できませんでした」＋オペレーター導線（存在の有無は答えない）
```

- 表示する項目：予約ID・プラン名・コース名・搭乗予定日・時間帯・人数・予約状況。氏名・連絡先・金額・決済情報は表示しません。
- 予約IDだけでは表示しません。予約サイト API がない間の照会先は「予約管理」シート（予約イベントで LINE ユーザーIDが紐づいた予約）です。
- 予約内容は応答（reply）でだけ送ります。プッシュでは送りません。
- 入力待ちは10分。途中でリッチメニューや定型語（「予約」「FAQ」など）を操作すると中断します。

### 予約変更・キャンセル・オペレーターに相談

| ボタン | 処理 |
|---|---|
| 予約変更 | 予約をもう一度本人確認し、変更可否を確認。不可なら理由と相談導線。可なら予約サイトの変更画面（予約サイトのホストのみ）へ、なければ「担当者が変更条件と差額を確認のうえ承ります」 |
| キャンセル | 同じく可否を確認し、キャンセル規定・料金の目安を表示。予約サイトのキャンセル画面（最終確認あり）へ、なければ担当者へ。ボタンを押しただけでは取り消しません |
| オペレーターに相談 | 予約IDを添えて相談内容を受け付け、有人対応へ（5章） |

GAS は予約の変更・取消を行いません。予約サイトに利用者向けの変更・キャンセル画面ができるまでは、担当者（管理画面の既存の変更処理）が対応します。API の仕様は [reservation-api.md](reservation-api.md)。

## 4. お問い合わせ（4項目）

| 項目 | postback | 処理 |
|---|---|---|
| チャーター見積 | `a=inq_cat&c=4` | 希望日時・出発地・目的地・搭乗人数・利用目的・その他の要望を案内（未定でも可）→ 受信 → 受付・保存 → 有人対応へ。料金は GAS で算出・確約しない |
| フライト予約について | `a=inq_cat&c=1` | 公式サイトの予約ページ（未公開なら準備中）を案内。解決しなければ「オペレーターに相談」ボタン。受付・停止はしない |
| その他のお問い合わせ | `a=inq_cat&c=5` | 自由入力 → 受信 → 受付・保存 → 有人対応へ |
| オペレーターに相談 | `a=inq_operator` | 相談内容の入力 → 受信 → 受付・保存 → 有人対応へ |

予約確認・変更（旧 c=2）と天候・運航（旧 c=3）はメニューから外しました。古いトーク画面のボタンが押された場合は、それぞれ予約確認・FAQ ページの案内に振り替えます。

## 5. 共通：有人対応への引き継ぎ（`handoffToOperator_`）

1. 同じ Webhook イベントで受付済みなら、同じ受付IDを案内して終了（受付IDを重複発行しない。シートの「LINEイベントID」で照合）
2. 受付IDを発行（`INQ-YYYYMMDD-NNNN`）
3. 受付完了を1回返信
4. 「問い合わせ管理」に保存（対応状況=未対応、自動返信有効=FALSE、LINEイベントID）
5. 入力待ちを終了し、自動返信の停止を記録
6. 運営に通知（既存の通知先 `ADMIN_NOTIFY_TARGET`／`ADMIN_EMAIL`。新しい通知の仕組みは追加していない）
7. 担当者が LINE Official Account Manager のチャットで返信し、対応状況を更新
8. 完了したら、その行の自動返信有効を TRUE に戻す（次のメッセージから自動返信を再開）

有人対応中は、FAQ・予約ID入力・キーワード・リッチメニューの準備中案内など、どの自動返信も割り込みません。詳細は [operator.md](operator.md)。

### 対応状況（記録用）

未対応 ／ 対応中 ／ お客様回答待ち ／ 見積・社内確認中 ／ 完了 ／ キャンセル・取下げ

対応状況は自動返信に影響しません（自動返信は「自動返信有効」だけで決まります）。既存の値（「対応完了」など）は変更しません。

## 6. よくある質問

リッチメニューの「よくある質問」は公式サイトの FAQ ページ（`FAQ_PAGE_URL`）へ移動します。FAQ ページは未公開のため未設定で、タップすると「準備中」と案内します。

- FAQ ページに載せるカテゴリ：天候・運航／料金・お支払い／予約変更・キャンセル／搭乗条件・持ち物／その他。FAQ ページには LINE の問い合わせへの導線を設けてください（予約サイト側の作業）。
- トークで「FAQ」と送った場合は、FAQ ページがあればページへ、なければ従来どおり「FAQ」シートの一覧を表示します。キーワードによる FAQ 自動回答も従来どおりです。

## 7. 状態の管理

| 状態 | 保存先 | 期間 | 終了 |
|---|---|---|---|
| 有人対応中 | 「問い合わせ管理」自動返信有効=FALSE（正本）＋スクリプトプロパティ | TRUE に戻すまで | シートで TRUE／管理メニュー |
| 予約確認の入力待ち | キャッシュ `rsv:<LINEユーザーID>` | 10分 | 表示・失敗・入力をやめる・メニュー操作 |
| 問い合わせ内容の入力待ち | キャッシュ `inq:<LINEユーザーID>` | 30分 | 受付・入力をやめる・メニュー操作 |

入力待ちは同時に1つだけです。状態は応答が LINE に受理された場合だけ変更します（偽装イベントで他人の状態を変えさせない）。
