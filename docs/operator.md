# 有人オペレーター対応と「自動返信有効」

顧客ごとの Bot 自動返信を、「問い合わせ管理」シートの **「自動返信有効」列（TRUE / FALSE）** で切り替えます。お問い合わせで「オペレーターに相談」を選ぶと、自動で FALSE になります。担当者は **LINE Official Account Manager のチャット画面**から直接返信します。専用のチャット画面は作りません。

実装: `src/gas/12_Operator.gs`　テスト: `tests/operator.test.js`

## 1. 「自動返信有効」列

| 値 | 動き |
|---|---|
| `TRUE` | Bot の自動返信を行う |
| `FALSE` | その顧客への Bot の自動返信を**すべて停止**する（チャット画面からの有人返信は可能） |
| 空欄 | 指定なし。判定に使わない（既存の問い合わせ行は空欄のまま） |

- 列は「問い合わせ管理」の**末尾**（備考の右）に追加します。既存の列の位置・既存の行（問い合わせ履歴・対応状況・担当者など）は変更しません。
  - 「シート列・設定行の補完」で追加されます。未実行でも、GAS が最初に問い合わせ行を書き込むときに自動で追加されます。
- 新しく作る行の値：通常の問い合わせ（5種別・「担当者に送る」）は `TRUE`、「オペレーターに相談」は `FALSE`。
- 入力は `TRUE` / `FALSE`（大文字小文字・前後の空白は無視）。シートが自動変換した真偽値（TRUE / FALSE）も同じに扱います。それ以外の値（例「はい」）は判定に使わず、管理メニューの状況確認に【要確認】と表示します。
- 「補完」でプルダウン（TRUE / FALSE）を設定します。**チェックボックスにはしません**。空欄のセルが FALSE と表示・解釈され、既存の顧客がすべて停止扱いになるのを防ぐためです。
- **「対応状況」は自動返信に影響しません**。未対応／対応中／対応完了 は対応の進み具合の記録としてそのまま使います（以前の版の「対応完了で再開」はやめ、「自動返信有効」に一本化しました）。

## 2. 同じ顧客に複数の問い合わせがある場合の優先順位

その顧客（LINEユーザーID）の行のうち、「自動返信有効」が TRUE / FALSE の行だけを対象にします。

1. **受付日時が最も新しい行**の値で決まる
2. 受付日時が同じ（または読めない）場合は、**シート上で下にある行**
3. 対象の行が1つもなければ **TRUE**（自動返信する）

| 例（同じ顧客の行） | 結果 |
|---|---|
| 10/01 FALSE、10/02 TRUE、10/03 空欄 | TRUE（10/02 が判定行。空欄は無視） |
| 10/01 TRUE、10/05「オペレーターに相談」FALSE | FALSE（10/05） |
| 10/05 FALSE の行を TRUE に変更 | TRUE（次のメッセージから再開） |
| 10/01 の行だけ FALSE に変更（10/02 が TRUE） | **TRUE のまま**。より新しい行が優先されます |

- シートを並べ替えても、受付日時で判定します。
- 再開するときは、**判定行（通常は最新の「オペレーター相談」の行）を TRUE** にします。古い行が FALSE のままでも、新しい行が TRUE なら再開します。
- 管理メニュー「自動返信の状況」に、判定行と、より新しい行に上書きされている行を表示します。
- 停止中の顧客は「オペレーターに相談」を押しても返信しない（イベント自体に応答しない）ため、停止中に新しい行が増えることはありません。

## 3. 流れ

```text
利用者：「お問い合わせ」（リッチメニュー／「お問い合わせ」と送信／クイックリプライ）
   └→ 種別選択（既存5種別 ＋「オペレーターに相談」）
        └→「オペレーターに相談」（postback a=inq_operator）
             1. 受付返信「担当者（オペレーター）におつなぎします … 受付ID：INQ-…」
             2. 問い合わせ管理に1行追加（種別「オペレーター相談」・対応状況「未対応」・自動返信有効「FALSE」）
             3. 停止を内部記録（スクリプトプロパティ）
             4. 運営に通知（ADMIN_NOTIFY_TARGET の LINE ／ ADMIN_EMAIL のメール）
担当者：LINE Official Account Manager → チャット で返信（FALSE の間も可能）
        必要に応じて 対応状況・担当者・回答日時 を入力
担当者：対応が終わったら、その行の「自動返信有効」を TRUE にする
   └→ その顧客から次にメッセージが届いた時点で自動返信を再開
```

- シートで直接 FALSE にした顧客（「オペレーターに相談」を押していない顧客）も、次のメッセージから停止します。
- 自動返信はメッセージへの返信として送るため、「TRUE にした後の最初のメッセージから再開」になります。再開時に利用者へお知らせは送りません（配信数を消費しないため）。
- 既存のお問い合わせ（5種別の入力・保存）、「担当者に送る」、FAQ、リッチメニュー、予約確認・予約通知の動きは変わりません。予約サイトからの通知（プッシュ）は「自動返信」ではないため、FALSE の顧客にも送ります。

## 4. 停止中（FALSE）の動き

| イベント | 動き |
|---|---|
| テキスト・画像・スタンプ等のメッセージ | **返信しない**。停止した件数と最終受信時刻だけ記録します。本文は保存しません（担当者はチャット画面で確認） |
| リッチメニュー・クイックリプライ（postback） | **返信しない**（準備中案内、FAQ、お問い合わせも含む） |
| 「予約」「FAQ」などの定型語 | **返信しない** |
| 友だち再追加（follow） | あいさつは送りません。プロフィール API で友だちと確認できた場合だけ、顧客管理を「友だち」に戻します |
| ブロック（unfollow） | 通常どおり顧客管理に反映します |
| エラー | 通常どおり「エラーログ」シートに記録します |
| グループ・トークルーム | 対象外（1対1トークのみ） |

他の顧客には影響しません。

## 5. スクリプトプロパティとの整合

- **正本はシート**です。スクリプトプロパティ `OPERATOR_MODE:<LINEユーザーID>` は「停止中」の内部記録で、判定行の受付ID・停止開始時刻・停止した件数・最終受信時刻だけを持ちます（本文・個人情報は入れません）。
- その顧客からイベントが届くたびにシートを読んで判定し、プロパティをシートに合わせます。

| シート | プロパティ | 受信時の処理 |
|---|---|---|
| FALSE | なし | プロパティを作成（シートで手動停止） |
| FALSE | あり（別の受付ID） | 受付IDを判定行に更新 |
| TRUE または指定なし | あり | プロパティを削除（シートで手動再開） |
| 一致 | 一致 | 何もしない |

- 管理メニュー「自動返信の状態を同期」で、全顧客をまとめて合わせることもできます。この操作ではシートの値を変更しません。
- 例外は2つです。
  - **シートを読めない場合**：プロパティで判断します（あり＝停止）。エラーログ `operator.status_check_failed` に記録します。
  - **停止記録の根拠となる行がない場合**（受付返信後にシート保存が失敗したなど）：自動では再開しません。状況確認に【要確認】と表示します。その受付IDの行を追加して TRUE / FALSE を入れると、シートに従います。
- **旧版からの移行**：以前の版（対応状況「対応完了」で再開）のプロパティが残っていて、その行の「自動返信有効」が空欄の場合は、対応状況から一度だけ値を書き込みます（対応完了→TRUE、それ以外→FALSE）。旧版は本番未反映のため、通常は発生しません。

## 6. 管理メニュー（お問い合わせ）

| 項目 | 内容 |
|---|---|
| 自動返信の状況（オペレーター対応） | 停止中の顧客（判定行の受付ID・種別・対応状況・担当者・停止からの経過時間・停止件数）と、【要確認】（行のない停止記録、TRUE/FALSE 以外の値）、上書きされている行、シートと内部記録の差を表示します。読み取りのみです。LINE ユーザーID は表示しません |
| 選択中の顧客の自動返信を再開（TRUEに） | 「問い合わせ管理」で選んだ行の顧客について、「自動返信有効」が FALSE の行を**すべて** TRUE にし、内部記録も削除します。対応状況・担当者は変更しません。確認ダイアログあり。利用者へのメッセージ送信はしません |
| 自動返信の状態を同期 | シートに合わせて内部記録を修正します（5章）。確認ダイアログあり |

いずれも `ADMIN_USERS` の確認を行います。通常の再開は、シートで TRUE にするだけで足ります。

## 7. 文面の変更

「通知テンプレート」の `OPERATOR_START` を `有効=ON` にすると、その本文で返信します（管理台帳には承認済みの文面が OFF で登録済み）。本文に `{{受付ID}}` があれば受付IDに置き換え、ない場合は末尾に `🔖 受付ID：…` を付けます。OFF のときは GAS の予備の文面を使います。

予備の文面（`12_Operator.gs` `DEFAULT_OPERATOR_START_TEXT`）:

```text
💬 担当スタッフへおつなぎいたします。
ご相談内容をこのトークにお送りくださいませ。確認のうえ、担当者より順次ご返信いたします。

※担当者の対応中は、自動返信を一時停止いたします。
🔖 受付ID：INQ-…
```

自動返信有効=FALSE の間は、停止中・再開のお知らせを含め、GAS からは何も送りません。文体・絵文字のルールは README の「14. メッセージの文言」を参照してください。

## 8. LINE Official Account Manager の設定

| 設定 | 値 |
|---|---|
| チャット | **オン**（担当者が返信するために必要） |
| Webhook | **オン**（オフにすると全顧客の自動返信が止まります） |
| あいさつメッセージ | オフ（GAS が送信） |
| 応答メッセージ | オフ（GAS の自動返信と重複するため） |

- 「LINE接続チェック」で、チャットのオン／オフを表示します（Bot 情報 API の `chatMode`）。
- FALSE の顧客にも、チャット画面からの返信はそのまま届きます。GAS は返信を止めるだけで、チャット画面の操作には関与しません。
- 管理画面の表示名・料金上の扱いは変わることがあります。本番前に LINE の最新のヘルプで確認してください（実機での確認は未実施です）。

## 9. 安全性（GAS単体受信＝署名検証なし）

| 操作 | 条件 |
|---|---|
| 「オペレーターに相談」での停止・記録・運営通知 | 受付返信が LINE に受理された（本物の応答トークン）場合のみ。偽装イベントで他人の自動返信を止めることはできません |
| 再開 | Webhook からは**不可**。シートの TRUE か、管理メニュー（`ADMIN_USERS`）のみ |
| 停止中のイベント | 返信しないため真偽を確認できません。本文の保存・通知はせず、件数のみ記録します |
| シートの編集者 | 「自動返信有効」を変更できます。シートの編集権限は信頼できる担当者に限定してください |

## 10. エラーログ（発生元「オペレーター対応」）

| コード | 意味・対処 |
|---|---|
| `operator.notify_failed` | 運営通知ができませんでした。`ADMIN_NOTIFY_TARGET`（ID管理）・`ADMIN_EMAIL` を確認し、「自動返信の状況」で対象を確認してください |
| `operator.save_failed` | 受付返信後、問い合わせ管理への保存に失敗しました。停止は記録済みです（5章の例外）。運営通知にも【要対応】が付きます |
| `operator.status_check_failed` | 問い合わせ管理を読めませんでした。内部記録で判断しています。次の受信時に再確認します |
| `operator.state_save_failed` / `operator.migrate_failed` | 内部記録の更新・旧版の移行に失敗しました。「自動返信の状態を同期」を実行してください |
| `operator.reply_failed` / `operator.ack_push_failed` | 署名検証済み（リレー）経路で受付返信に失敗しました。プッシュでの再通知を試みます |

## 11. 制約

- 再開は「次のメッセージ受信時」です。TRUE にした瞬間に、利用者へ何かを送ることはしません。
- TRUE に戻し忘れると、その顧客の自動返信は止まったままです。「自動返信の状況」で経過時間を定期的に確認してください。自動のタイムアウトはありません。
- 停止中に届いたメッセージの本文は GAS に残りません。チャット画面の履歴を参照してください。
- 受信のたびに「問い合わせ管理」を読みます。行数が非常に多くなった場合（数万行）は、古い行を別シートに移すことを検討してください（行の削除・移動は担当者の判断で行います）。

## 12. 本番への反映手順（未実施）

このリポジトリの変更は、**本番GAS・LINE にはまだ反映していません**。本番の Web アプリはバージョン5（build `2026-10-21.3-gas-only`）で、未反映のエラーログ機能・リッチメニュー修正・オペレーター対応も同時に反映されます。

1. **本体GASにコードを反映**（スクリプトID `1zlkPtaZ…ff` は変更しない。再作成しない）：`clasp push`。エディタに `12_Operator.gs` があることを確認します。
   - 管理メニューはライブラリを開発モード（HEAD）で読み込むため、この時点で管理メニュー側は新しいコードで動きます。
2. **Web アプリを新バージョンで更新**：デプロイ → デプロイを管理 → 既存のウェブアプリを編集 → 「新バージョン」。新しいデプロイは作らず、URL を変えません。反映まで1〜2分かかります。
3. **管理メニュー用GASを更新**（スクリプトID `1rK0ECYP…SSd`。本体GASと混同しない）：`src/sheet-admin/Code.gs` を、スプレッドシートの「拡張機能 → Apps Script」の `Code.gs` に反映します。
4. **シート列・設定行の補完**：「自動返信有効」列（末尾）、選択肢、`OPERATOR_START`（OFF）が追加されます。既存データは変更しません。
5. **LINE接続チェック**：「Web アプリの反映状況」が【OK】（build `2026-10-28.1-messages` 以降）、チャットが【OK】オン、疎通テスト HTTP 200 を確認します。
6. **LINE Official Account Manager → 応答設定**：チャット オン、Webhook オン。
7. **実機確認**（テスト用アカウントで）
   1. 「お問い合わせ」→「オペレーターに相談」→ 受付IDつきの返信が届く
   2. 問い合わせ管理に「オペレーター相談／未対応／FALSE」の行、運営通知が届く

   4. チャット画面から返信でき、利用者に届く
   5. その行を TRUE にして「予約」と送ると自動返信が返る
