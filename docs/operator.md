# 有人オペレーター対応

お問い合わせの種別選択に「オペレーターに相談」を追加しました。選択した利用者には、担当者が **LINE Official Account Manager のチャット画面**から直接返信します。対応中は、その利用者への GAS の自動応答を止めます。専用のチャット画面は作りません。

実装: `src/gas/12_Operator.gs`　テスト: `tests/operator.test.js`

## 1. 流れ

```text
利用者：「お問い合わせ」（リッチメニュー／「お問い合わせ」と送信／クイックリプライ）
   └→ 種別選択（既存5種別 ＋「オペレーターに相談」）
        └→「オペレーターに相談」（postback a=inq_operator）
             1. 受付返信「担当者（オペレーター）におつなぎします … 受付ID：INQ-…」
             2. 問い合わせ管理に1行追加（種別「オペレーター相談」・対応状況「未対応」）
             3. この利用者をオペレーター対応モードにする（自動応答を停止）
             4. 運営に通知（ADMIN_NOTIFY_TARGET の LINE ／ ADMIN_EMAIL のメール）
担当者：LINE Official Account Manager → チャット で返信
        必要に応じて 対応状況「対応中」・担当者・回答日時 を入力
担当者：対応が終わったら 対応状況 を「対応完了」にする
   └→ その利用者から次にメッセージが届いた時点で、自動応答に戻る
```

- 既存のお問い合わせ（5種別の入力・保存）、「担当者に送る」、FAQ、リッチメニューの動きは変わりません。
- 自動応答はメッセージへの返信として送るものです。そのため「対応完了以降に届いた最初のメッセージから自動応答に戻る」動きになります。再開時に、利用者へお知らせを送ることはしません（配信数を消費しないため）。

## 2. オペレーター対応モード中の動き

| イベント | 動き |
|---|---|
| テキスト・画像・スタンプ等のメッセージ | **返信しない**。停止した件数と最終受信時刻だけ記録します。本文は保存しません（担当者はチャット画面で確認します） |
| リッチメニュー・クイックリプライ（postback） | **返信しない**（「予約する」の準備中案内、FAQ、お問い合わせも含む） |
| 「予約」「FAQ」などの定型語 | **返信しない** |
| 友だち再追加（follow） | あいさつは送りません。友だちであることをプロフィール API で確認できた場合だけ、顧客管理の状態を「友だち」に戻します |
| ブロック（unfollow） | 通常どおり顧客管理に反映します（モードはそのまま） |
| エラー | 通常どおり「エラーログ」シートに記録します |
| グループ・トークルーム | 対象外（1対1トークのみ） |

他の利用者には影響しません。

## 3. 「問い合わせ管理」シート

既存の列はそのまま使います。列の追加はありません。

| 列 | オペレーター相談の行での値 |
|---|---|
| 受付ID | `INQ-yyyyMMdd-NNNN`（既存の問い合わせと同じ採番） |
| LINEユーザーID | 利用者の ID |
| 種別 | `オペレーター相談` |
| 内容 | `オペレーター対応の依頼（LINE表示名：…）` |
| 対応状況 | `未対応` →（任意）`対応中` → **`対応完了`**（＝自動応答を再開） |
| 担当者・回答日時 | 担当者が入力（GAS は変更しません） |
| 備考 | `オペレーター対応（自動応答停止中）`。GAS単体受信の場合は `GAS単体受信（応答トークン確認済み・署名未検証）` も付きます |

- 「シート列・設定行の補完」を実行すると、「対応状況」列に **未対応 / 対応中 / 対応完了** の選択肢（プルダウン）が付きます。既存の値（例「完了」）は変更しません。選択肢以外の値は、警告表示だけで入力は可能です。
- 自動応答を再開する値は **`対応完了` だけ**です（前後の空白は無視）。「完了」などでは再開しません。
- 行を削除すると自動では再開できません。その場合は管理メニューから終了してください（4章）。

## 4. 管理メニュー（お問い合わせ）

| 項目 | 内容 |
|---|---|
| オペレーター対応状況 | 対応中の受付ID、対応状況、担当者、経過時間、停止した自動応答の件数を表示します（読み取りのみ）。LINE ユーザーID は表示しません |
| オペレーター対応を終了（選択中の行） | 「問い合わせ管理」で選択した1行の受付IDについて、すぐに自動応答を再開します。対応状況が「対応完了」でなければ「対応完了」に更新します。確認ダイアログあり。利用者へのメッセージ送信はしません |

どちらも `ADMIN_USERS` の確認を行います。通常の終了は、対応状況を「対応完了」にするだけで足ります。

## 5. 文面の変更

「通知テンプレート」に `OPERATOR_START` を追加しました（「シート列・設定行の補完」で `有効=OFF` で追加されます）。`有効=ON` にすると、その本文で返信します。末尾には `受付ID：…` が自動で付きます。OFF のときは既定文を使います。

既定文:

```text
担当者（オペレーター）におつなぎします。
このトークにご相談内容をお送りください。担当者が確認のうえ、このトークで順次返信いたします。

※担当者の対応が終わるまで、自動応答は停止します。

受付ID：INQ-…
```

対応期限（○時間以内など）は、営業時間が確定するまで約束しない方針のままです。

## 6. LINE Official Account Manager の設定

担当者がチャット画面から返信するには、応答設定で **チャットをオン**にします。

| 設定 | 値 |
|---|---|
| チャット | **オン**（オペレーター対応に必要） |
| Webhook | **オン**（オフにすると GAS の自動応答がすべて止まります） |
| あいさつメッセージ | オフ（GAS が送信） |
| 応答メッセージ | オフ（GAS の自動応答と重複するため） |

- 管理メニュー「LINE接続チェック」で、チャットのオン／オフを表示します（LINE の Bot 情報 API の `chatMode`）。
- チャットとWebhookを両方オンにしても、GAS の動き（自動応答・記録）は変わりません。
- 管理画面の表示名・料金上の扱いは変わることがあります。本番前に LINE の最新のヘルプで確認してください（実機での確認は未実施です）。

## 7. 保存先と安全性

- モードの保存先は、本体GASのスクリプトプロパティ `OPERATOR_MODE:<LINEユーザーID>` です。値は受付ID・開始時刻・停止件数・最終受信時刻で、本文や個人情報は入れません。キャッシュと違って、時間が経っても消えません。
- 状態の正本は「問い合わせ管理」の対応状況です。モード中の利用者からイベントが届くたびに、該当行を確認します。

GAS単体受信（署名検証なし）の前提で、次のように制限しています。

| 操作 | 条件 |
|---|---|
| モードの開始・記録・運営通知 | 受付返信が LINE に受理された（本物の応答トークン）場合のみ。偽装イベントでは、他人をモードにして自動応答を止めることはできません |
| モードの解除 | Webhook からは**不可**。シートの「対応完了」か、管理メニュー（`ADMIN_USERS`）のみ |
| モード中のイベント | 返信しないため、応答トークンで真偽を確認できません。本文の保存・通知はせず、件数のみ記録します（偽装イベントでもシート・通知に影響しません） |
| シートを確認できない場合 | 安全側（返信しない）に倒し、エラーログ `operator.status_check_failed` に記録します |

## 8. エラーログ（発生元「オペレーター対応」）

| コード | 意味・対処 |
|---|---|
| `operator.notify_failed` | 運営通知ができませんでした。`ADMIN_NOTIFY_TARGET`（ID管理）・`ADMIN_EMAIL`（スクリプトプロパティ）を確認し、「オペレーター対応状況」で対象を確認してください |
| `operator.save_failed` | 受付返信後、問い合わせ管理への保存に失敗しました。モードは開始済みです。運営通知にも【要対応】が付きます。行を手動で追加するか、「オペレーター対応を終了」で解除してください |
| `operator.status_check_failed` | 対応状況を読めませんでした（返信は停止したまま）。一時的なものなら、次の受信時に再確認されます |
| `operator.reply_failed` / `operator.ack_push_failed` | 署名検証済み（リレー）経路で受付返信に失敗しました。プッシュでの再通知を試みます |

## 9. 制約

- 再開は「次のイベント受信時」です。対応完了にした瞬間に、利用者へ何かを送ることはしません。
- 担当者が「対応完了」にし忘れると、その利用者の自動応答は止まったままです。「オペレーター対応状況」で経過時間を定期的に確認してください。自動のタイムアウトはありません。
- モード中に届いたメッセージの本文は GAS には残りません。記録が必要な場合は、チャット画面の履歴を参照してください。

## 10. 本番への反映手順（未実施）

このリポジトリの変更は、**本番GAS・LINE にはまだ反映していません**。反映するときは次の順で行います。本番の Web アプリはバージョン5（build `2026-10-21.3-gas-only`）で、未反映のエラーログ機能・リッチメニュー修正も同時に反映されます。

1. **本体GASにコードを反映**（スクリプトID `1zlkPtaZ…ff` は変更しない。再作成しない）
   `clasp push`（`.clasp.json` の `rootDir` は `src/gas`）。エディタに `12_Operator.gs` があることを確認します。
   - 管理メニューはライブラリを開発モード（HEAD）で読み込むため、この時点で管理メニュー側は新しいコードで動きます。
2. **Web アプリを新バージョンで更新**
   デプロイ → デプロイを管理 → 既存のウェブアプリを編集 → バージョン「新バージョン」→ デプロイ。新しいデプロイは作らず、URL を変えません。反映まで1〜2分かかります。
3. **管理メニュー用GASを更新**（スクリプトID `1rK0ECYP…SSd`。本体GASと混同しない）
   `src/sheet-admin/Code.gs` の内容を、スプレッドシートの「拡張機能 → Apps Script」の `Code.gs` に反映します。スプレッドシートを開き直すと「お問い合わせ」メニューが表示されます。
4. **シート列・設定行の補完**（初期設定）
   「対応状況」の選択肢と、`OPERATOR_START` テンプレート（OFF）が追加されます。既存データは変更しません。
5. **LINE接続チェック**
   「Web アプリの反映状況」が【OK】（build `2026-10-21.6-operator`）であること、チャットが【OK】オンであることを確認します。疎通テストで HTTP 200 も確認します。
6. **LINE Official Account Manager → 応答設定**：チャット オン、Webhook オン（6章）
7. **実機確認**（テスト用アカウントで）
   1. 「お問い合わせ」→「オペレーターに相談」→ 受付IDつきの返信が届く
   2. 問い合わせ管理に「オペレーター相談／未対応」の行、運営通知が届く
   3. 「予約」「FAQ」と送っても、リッチメニューを押しても自動返信がない
   4. チャット画面から返信でき、利用者に届く
   5. 対応状況を「対応完了」にして「予約」と送ると、自動返信が返る
   6. 「お問い合わせ → オペレーター対応状況」が「いません」になる

**戻し方**: デプロイを管理 → 既存のウェブアプリを編集 → バージョン5を選択。オペレーター対応中の利用者がいた場合、旧コードは `OPERATOR_MODE:` を参照しないため、通常の自動応答に戻ります（プロパティは残っても動作に影響しません）。
