# エラーログ

本体GASで発生したエラーだけを、管理スプレッドシートの「エラーログ」シートに記録します。

## シート

| 列 | 内容 |
|---|---|
| 発生日時 | 日本時間（`yyyy-MM-dd HH:mm:ss`） |
| 重要度 | `ERROR` / `FATAL`（FATAL＝要求・処理全体の失敗、またはデータが失われる恐れがあるもの） |
| 発生元 | Webhook / LINE API / FAQ / 問い合わせ / 顧客管理 / 予約 / 通知 / 管理メニュー / トリガー / 設定 |
| 関数名 | 例外が発生した関数（スタックトレースの先頭。取れない場合は発生箇所のコード） |
| エラーメッセージ | 機密情報を除いたメッセージ（500文字まで） |
| エラー詳細・スタックトレース | 発生箇所のコード（例 `notify.push_failed`）、補足情報、HTTP ステータス、抑制件数、スタックトレース |
| 関連ID | 送信ID・受付ID・予約ID・イベントID・操作名など（LINE ユーザーIDは含めない） |
| 対応状況 | 初期値「未対応」（未対応 / 対応中 / 対応済み / 対象外 から選択） |

- 1行目（ヘッダー）を固定し、フィルターを設定しています。
- 重要度で色分けします（FATAL＝赤、ERROR＝橙）。
- シートは、最初のエラー発生時、管理メニュー「エラーログ設定・動作確認」、または「シート列・設定行の補完」のいずれかで自動作成されます。既存のシートとデータは変更しません。

## 記録するもの・しないもの

| 記録する | 記録しない |
|---|---|
| `logError_()` の呼び出し（ERROR / FATAL） | `logInfo_()`・`logWarn_()` |
| Webhook 処理の失敗（LINE API 5xx 等）、doPost の想定外エラー（FATAL） | 正常な Webhook 受信・正常な LINE 送信 |
| LINE 送信失敗（通知・問い合わせ受付・運営通知） | 偽造・期限切れの応答トークンが LINE に拒否されたこと（400。警告のみ） |
| 問い合わせ保存失敗（返信後の保存失敗は FATAL） | 想定内の分岐（既定リッチメニューなし 404、JSON 解析の代替処理など） |
| FAQ・テンプレート・ID管理の読み込み失敗 | |
| 予約 API・LIFF の想定外エラー（FATAL） | |
| 定期トリガー（リマインド・再送）の失敗（FATAL。実行履歴にも失敗として残す） | |
| 管理メニューの操作失敗、ライブラリ呼び出し自体の失敗 | |
| リッチメニュー登録途中の削除失敗（従来は記録なし） | |

## 重複の抑制

- 「発生箇所＋メッセージ（数字は同一視）」が同じエラーは、ERROR は10分、FATAL は1分に1件だけ記録します。
- 省略した件数は、次に記録する行の詳細に「直前の同一エラー N 件は重複のため記録を省略」と残します。
- 発生箇所やメッセージが違うエラーは、それぞれ記録します。
- 抑制はスクリプトキャッシュを使っています。キャッシュが消えた場合は、抑制期間内でも記録されることがあります（記録漏れにはなりません）。

## 機密情報の扱い

- 次の情報はマスクまたは除去します。
  - `Bearer` トークン
  - URL の `token` / `id_token` / `lineUserId` / `key` / `code` パラメータ
  - LINE のユーザー・グループID
  - メールアドレス、電話番号、JWT
- 補足情報のうち、`text` / `message` / `content` / `token` / `secret` / `phone` / `email` / `内容` / `氏名` などのキーは `[REDACTED]` にします。`userId` / `to` は記録しません。
- Webhook の本文や利用者のメッセージは記録しません。

## 安全性

- ログ処理（シート作成・書き込み）が失敗しても例外を投げず、本来の処理を続けます（実行ログに `errorlog.write_failed` を出力）。
- LINE からの Webhook には、引き続き HTTP 200（HtmlService）で応答します。
- 書き込みにはスクリプトロックを使いません（ロック取得中の処理からも呼ばれるため）。`appendRow` は1行単位で原子的です。

## 管理メニュー

「SKY STANDARD → システム管理」から操作します。

- **エラーログを開く**: シートを開き、最終行を選択します。未作成の場合は作成方法を案内します。
- **エラーログ設定・動作確認**:
  - シートの作成・書式設定（ヘッダー固定・フィルター・色分け・選択肢）と、記録の仕組みを表示します。
  - 続けて確認ダイアログで「はい」を選んだ場合だけ、テストエラーを1件記録します（重要度 ERROR、発生元「管理メニュー（動作確認）」）。
  - 通常の運用中にテストエラーが自動で作られることはありません。

## 過去のエラーの取得について（制約）

GAS の実行履歴にある過去のエラーは、自動では取得できません。

- Apps Script API の `processes.list` で得られるのは、関数名・状態（失敗など）・開始時刻・実行時間だけです。エラーメッセージやスタックトレースは返りません。
- エラーの内容は Cloud Logging にあります。ただし、既定の（Google 管理の）Cloud プロジェクトに紐づくスクリプトは、Logging API から読めません。読むには、スクリプトを標準の Google Cloud プロジェクトに切り替え、Logging API と追加の OAuth スコープを設定する必要があります。

このため本機能では、**今後発生するエラーを記録する**方式にしています。過去のエラーは Apps Script エディタの「実行数」画面で確認してください。

## 本番反映手順

| 対象 | 変更 | 反映方法 |
|---|---|---|
| 本体GAS（`1zlkPtaZ…`） | `00_Config.gs`（版 `2026-10-21.4-errorlog`）、`01_Webhook.gs`、`08_RichMenu.gs`、`10_Logger.gs`、`11_Admin.gs` | `clasp push` のあと、**ウェブアプリを「新バージョン」でデプロイ**（URL は不変） |
| 管理メニューGAS（`1rK0ECYP…`） | `Code.gs`（メニュー2項目・ライブラリ失敗時の記録） | `npm run sheet-admin:push`、または `src/sheet-admin/Code.gs` をエディタに貼り付けて保存 |
| スプレッドシート | 「エラーログ」シート（新規） | 反映後、メニュー「システム管理 → エラーログ設定・動作確認」で作成（または最初のエラー発生時に自動作成） |

1. `git pull` → `clasp push`（本体GAS）
2. 本体GAS：「デプロイ → デプロイを管理 → 編集 → バージョン：新バージョン → デプロイ」
3. 管理メニューGAS：`cd src/sheet-admin && clasp push --force`（`.clasp.json` の scriptId は `1rK0ECYP…`）
4. スプレッドシートを再読み込みし、「システム管理」に2項目が追加されたことを確認
5. 「エラーログ設定・動作確認」でシートを作成し、確認ダイアログで「はい」を選んでテストエラーを1件記録
6. 「LINE接続チェック → 疎通テスト」で、次を確認
   - Web アプリの版が `2026-10-21.4-errorlog` で【OK】
   - LINE 側の判定が HTTP 200
7. 動作確認でできたテスト行は、対応状況を「対象外」にするか削除してください

管理メニューの処理本体（`adminRun`）は、本体GASの保存済みコード（開発モードのライブラリ）を使います。そのため手順1の時点で反映されます。Webhook・定期トリガーは、手順2のデプロイ後に反映されます。
